# Personas and Evidence

## Primary persona: aquarium keeper

**Status:** supported by the Vision.

This person manages aquarium care across freshwater, saltwater, brackish,
planted, reef, shrimp, snail or mixed systems and needs understandable, low-friction
workflows for records, planned work and historical review. The Vision explicitly
names aquarium keepers as the intended user group; no skill level, household
model, number of aquariums or collaboration behavior is assumed.

For the first slice this is an **authenticated keeper**. Authentication protects
the private, durable care context; it does not establish collaboration roles.

## Candidate persona: public visitor

**Status:** deferred with public presentation.

This person may view deliberately published Aquarium information. No visitor
capability or public data is included in the first slice, and private care data
must never become public by inference.

## Candidate persona: collaborating caretaker

**Status:** pending evidence.

This may be relevant if one Aquarium is managed by more than one person. It is
not a confirmed user type and must not justify roles, invitations or sharing
features until a validated use case establishes the need.

## Candidate persona: device-assisted keeper

**Status:** pending evidence.

This is the primary persona using sensor-derived information, not a separate
market segment. It matters only if device input is validated as a product need.

No professional, administrator, retailer or veterinary persona is documented:
the current product material provides no evidence for them.
