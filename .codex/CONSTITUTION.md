# Project Constitution

## Philosophy

Veril should remain clear, useful and sustainable. Its evolution favors
understanding over short-term speed, and every change should improve reliability
or maintainability.

## Permanent principles

- Prefer simplicity before complexity.
- Reuse before duplication.
- Make small, incremental and reversible changes.
- Keep documentation synchronized with behavior and decisions.
- Keep technical debt visible and under control.
- Preserve consistent architecture and explicit boundaries.
- Prioritize maintainability over local convenience.
- Keep the domain understandable before optimizing framework integration.
- Prefer offline capability only where privacy and consistency remain safe.
- Keep operational cost visible and minimize unnecessary provider usage.
- Apply security and accessibility by default.
- Prefer composition over inheritance and explicit behavior over hidden magic.
- Measure before optimizing and document decisions that constrain future work.

## Quality

- Code and names must be readable and consistent.
- Tests must provide meaningful confidence.
- Dead code and duplicated configuration must not accumulate.
- Relevant problems must be visible before scope expands.

## AI

- Minimize context and avoid repository-wide exploration without need.
- Reuse context already loaded.
- Justify broad or hard-to-reverse changes.
- Ask before destructive changes.

## Evolution

Changing this constitution requires an explicit, conscious and documented
decision explaining the reason, scope and consequences.
